Full record: `docs/checkpoints/PHASE5_M0_MEMORY.md`.
- **5-2, 2026-10-18, user.** d3 determinism: a build-time alias gives the export and CPU-sampler path a second copy of d3-geo and d3-geo-projection whose `math.js` calls `dmath`; d3's files are never modified; interactive display keeps stock d3 with native math. Tolerances against stock d3 in fdlibm mode: 8 ULP forward, 32 ULP inverse, 128 ULP for Hammer's inverse (measured 103). Alias files are in `packages/projection/alias/` (not `build/`, which `.gitignore` excludes).
- **5-3, 2026-10-18, user.** Heightmap scales: orogen's two mappings (−5 to +6 km, and land-only 0 to 6 km) plus a custom range in metres; the mapping and range are written into the PNG as text. Mapping to grey happens after sampling in metres (cloud recommendation, accepted).
- **5-4, 2026-10-19, cloud (included in the M3 prompt).** Pixels outside a projection's outline: plain 16-bit greyscale (colour type 0) by default with outside pixels = 0, recorded in the PNG text; transparent-outside (grey plus alpha, type 4) is an option. Reason: most height-map consumers expect single-channel 16-bit. M2 had made type 4 the default; the golden hashes for the `fd.projection` probe keys were recorded in this phase, so re-recording them is expected and must be stated in the commit. Done in `ca50aae`.
- **5-5, 2026-10-18, user.** GPU shader projections: equirectangular, Mercator, Equal Earth, Mollweide, Natural Earth 1, Robinson, orthographic, stereographic, azimuthal equal-area, azimuthal equidistant. Every other projection uses the CPU path at reduced resolution.
- **5-6, 2026-10-18, agent.** Distortion at line and cusp poles uses extrapolation with an order estimated by Aitken's Δ² process instead of §3.7 rule 3's fixed "grows by more than 2× per halving" test, which misses slow divergences such as Mollweide's k ∝ δ^(−1/3) at its cusp (measured: 19.46 reported instead of ∞). Documented in `packages/projection/src/distortion.ts`. Done: §3.7 rule 3 carries a one-line correction (`2e77a5a`).
- **5-7, 2026-10-18, agent.** `rawScale` in the projection registry makes d3's stereographic (×2) and Robinson (×0.8487) raws true to their published definitions, so distortion values are absolute.
- **5-8, 2026-10-19, agent.** Exported vector geometry is resampled at 0.05 px (`EXPORT_PRECISION_PX`) instead of d3's √0.5 px: at the default, a Tissot circle split by Hammer's antimeridian lost 3.7% of its area (0.2% at 0.05 px). Interactive views keep d3's default. Reversible (one constant).
- **5-9, 2026-10-19, agent (M4).** GPU shaders do not use the GPU's built-in transcendental functions. Measured in Chromium (ANGLE on Metal): about 4e-4 absolute error, which displaced content by 0.1 to 0.6 px at 16× zoom and 0.5 px at the orthographic limb at 1× (visible). The shader carries float32 Cephes algorithms (sin, cos, atan, atan2, asin, acos, exp, log: Cody-Waite reduction and minimax polynomials); only sqrt and arithmetic come from the GPU. Alternatives: split-float (double-float) arithmetic (much slower, unnecessary once libm is accurate); CPU refinement (defeats the GPU path). Reversible.
- **5-10, 2026-10-19, agent (M4).** Where d3's formula cancels in float32, the shader uses a mathematically identical rearrangement: the azimuthal inverses return the raw unit vector (cos c, x sin c / z, y sin c / z) instead of atan2/asin; the azimuthal equidistant and equal-area forwards take sin c from the vector components instead of from cos c (antipode); Mollweide's inverse goes through u = π − 2|θ| with a series for u − sin u (poles). The round trip follows d3's rotation semantics: with a φ or γ rotation d3 recomputes λ from the vector (so at a raw pole λ is lost and pixels just beyond a pole line are outside), otherwise λ is kept. Visibility walk: stepping back to the previous triangle means the point is on the shared edge within float32 noise, and the walk stops (seen once: a ping-pong in Firefox/WebKit orthographic).
- **5-11, 2026-10-19, agent (M4).** Measured GPU against CPU (20k world, 10 projections × 7 views each including both polar aspects and 16× zooms on the antimeridian and next to a pole; Chromium, Firefox, WebKit on macOS arm64): screen displacement of the shader's point against d3's ≤ 0.0066 px at 1× and ≤ 0.0012 px at 16× (tolerances 0.02 and 0.05 px); in/out differences only within 0.02 px of the 0.5 px round-trip threshold, 1e-5 rad of a clip circle, Mercator limit or raw pole (0 elsewhere); triangle differs from the CPU sampler at ≤ 0.013% of pixels and nearest cell at ≤ 0.0063%, every one explained by float32 noise at an edge (the shader's triangle contains the shader's point to 1e-5 in normalised weight; its cell is nearest to it to 1e-6 rad); value error ≤ 1.6e-4 of the layer's range where the triangle agrees; walks ≤ 7 steps (bound 64). Float32 is therefore invisible at every zoom the app allows (1× to 16×). Cell positions are uploaded as float32 (an edge moves by at most 3e-8 rad, 0.2 m on Earth).
- **5-12, 2026-10-19, agent (M4).** Lookup data: one cube-map texel per triangle (3R × 2R, R = ⌈√(triangles/6)⌉; above cell density as §3.7 asks), built in the engine worker (3.4 s at 2.56M cells, measured in Node), walks ≤ 7 steps. Barycentrics relative to the triangle's first vertex (no cancellation at the triangle's scale). Flat data textures are R32UI/R32F, row width = the GPU's MAX_TEXTURE_SIZE; a mesh that does not fit (for example 2.56M cells on a GPU limited to 2048) falls back to the CPU path.
- **5-13, 2026-10-19, agent (M4).** Flat-map colours: barycentric layers interpolate the value and then apply the palette in the shader (orogen's `elevationToColor` and the globe's 4-stop ramp, ported), so a coastline is a sharp contour inside a triangle rather than a colour blend; categorical layers (Köppen, plates) take the nearest cell's colour. Output passes three.js's linear → sRGB transfer, as the globe's material does, so both views show the same colours. Vector-magnitude layers (wind, currents) interpolate the per-cell magnitude.
- **5-14, 2026-10-19, agent (M4).** Projections without a shader draw on the CPU path at half the linear resolution, sampled in the engine worker in bands of 16 rows (`projection.locate`), colourised on the main thread with the shader's rules; a newer render supersedes an older one. The flat map zooms from 1× to 16×.
- **5-15, 2026-10-19, agent (M5).** Flat-map UI: the controls sit above the map (globe/flat switch next to the layer select). Wheel zoom keeps the point under the cursor fixed; drag pans only when zoomed; changing projection resets zoom and pan, not rotation. Interactive overlays (graticule, coastlines, Tissot, outline) are SVG from stock d3 at the map's device-pixel size; the distortion heatmap is computed in the worker at a quarter of the linear resolution, one request at a time (the latest state is drawn when it finishes). Exports are always the whole outline at zoom 1 with the current projection and rotation, at a chosen width (height from the outline's aspect), through the exact path in the worker; zoomed-window export is not offered. Reversible.

## Phase 5b (editor core)

- **5b-1, 2026-10-19, agent.** Edit log (`packages/core/src/edits/`): append-only with a cursor; undo and redo move the cursor by **gesture** (strokes of one gesture share an id), and a new edit after an undo drops the redo tail (branches are note 36). No wall-clock merging: Godot's `undo_redo.cpp:95` merges within 800 ms of real time, which would make equal edit sequences give different hashes (group 5b G3). Hashes ignore `createdAt`, `author` and `label`. Edits and system switches are saved (`edits/log.ndjson.gz`, `edits/cursor.json`, `systems.json`) and added to a stage's input hash **only when present**, so every existing world hash, stage hash and golden is unchanged (full suite green). Alternatives: wall-clock merge (rejected), a snapshot stack like Azgaar's heightmap undo (rejected: not replayable, large). Reversible.
- **5b-2, 2026-10-19, agent.** Edits are applied by the stage that produces their target, to what it just computed and before any stage reads it (`StageContext.edits`; the runner hashes `stageEdits`). Terrain edits target `elevation` and are applied in the structured detail pass (before climate and drainage) and in the stock erosion stage (before climate); `koppen` and, in the structured pipeline, `plate` take categorical paint. Consequence found by test: the structured pipeline's downscaled temperature, precipitation and wind come from the 20k reference climate and have no local elevation term, so a 3000 m raise did not change the temperature. A lapse adjustment applies orogen's own rate (vendor `climate-config.js:47-48`, `temperature.js:875-878`) to the elevation change of edited cells only, in the layer's normalised units (the temperature range is −45 to +45 °C, `temperature.js:789-791`; a first version that forgot the normalisation was caught by the stock-pipeline test). Precipitation and winds are unchanged by an edit; large structural edits (moving a continent) need Phase 6b. Reversible.
- **5b-3, 2026-10-19, agent.** Seed tools: a **hotspot seed** is an additive Gaussian dome (height, σ = radius/3) and a **plate-boundary seed** is a ridge or trench along a stroke (height, half-width, noise-modulated). They are relief that climate and drainage then follow; they do not re-run orogen's tectonics, whose plate partition and reference structure stay fixed (invariant I2). Real plate seeds arrive with plate evolution (Phase 6b). Alternative: patch the ported hotspot placement in `port/elevation.ts` (about 10,800 lines of port) to take user sites: rejected as unsafe for parity and for I2. Reversible.
- **5b-4, 2026-10-19, agent.** System switches (`World.systems`, per stage id): `off` zero-fills the stage's outputs, `manual` zero-fills them and calls the stage's `manual` hook (the structured detail pass applies the edit log to flat terrain). The mesh stage and the reference pass are structure, not systems: `switchable: false`, and the runner rejects a switch on them. Stock stages have no `manual` hook (zero-filled only). The switch is part of the stage's input hash. Reversible.
- **5b-5, 2026-10-19, agent.** Tool vocabulary (group 5b E3): raise and lower (the falloff gives Azgaar's Elevate and Depress), smooth, flatten (Azgaar's Align, to the region mean or a height), terrace (new), noise (seeded simplex, replayable, unlike Azgaar's `Math.random` Disrupt), set, land and sea paint, categorical paint, hotspot and ridge seeds. Azgaar's template steps (Hill, Pit, Range, Trough, Strait, Mask) are a later stamp tool, not in 5b. Brush regions are stroke geometry (unit vectors, radius in radians, falloff) and are rasterised to cell weights by flood fill with exact arc distance, so a stroke re-rasterises onto any mesh (about the same area at 20k and 80k cells, tested).
- **5b-6, 2026-10-19, agent.** Parameter edits: target `{ kind: 'param', key: 'orogen.<name>' }`, op `set`, `payload.value`, merged in log order by `readParams`; they enter the input hash of every orogen stage, so a change re-runs from the mesh. The strict "nothing outside writes changed" audit cannot describe the mesh stage rebuilding the world, so runs after a parameter edit use `strict: false` (as the app does for large worlds). Reversible.
- **5b-7, 2026-10-19, agent.** Parameter registry scope: only the 14 world sliders are registered (levels: simple = the headline ones, advanced = the rest); the expert tier is present but empty, because orogen's ~446 constants are not overridable without touching `vendor/` and have no registry metadata yet. Presets set slider values only. **Limitations carried to the checkpoint:** no brush cursor or live GPU preview of an edit (the stroke applies on re-run), edits cover elevation, Köppen, plate paint (structured only) and parameters, the parity pipeline has no plate paint, and precipitation/wind are not recomputed from local edits (they come from the 20k reference mesh; large structural edits wait for Phase 6b). Reversible.

## Phase 5c (cartography v1)

- **5c-1, 2026-10-19, agent.** Conic projections (Albers = conic equal-area, Lambert conformal conic, conic equidistant), from d3-geo unmodified. The two standard parallels are a *view* parameter (`ViewOptions.parallels`, default 30°/60°, clamped to ±89.9°), so they travel with the view spec to the CPU path, every export and the distortion code; `ProjectionView.raw` is the raw projection for those parallels (`distortion.ts` uses it, not `spec.raw`). They have no shader (CPU path at reduced resolution, decision 5-14). Pole classes: Albers and equidistant are `line` (both poles are arcs), the conformal is `cusp`. **Lambert conformal is unbounded** on the side away from its apex (the far pole is at infinity; d3 clamps at ε = 1e-6 and the fit collapses): the view cuts the domain 30° short of that pole (raw latitude −60° to 90° for northern parallels; `ProjectionView.outline()` is that cap, used for the fit, the outline path and the export aspect), clips vector geometry to the image, and treats parallels that sum to ~0 (which is Mercator) as a cone by nudging one by 0.01°. The exact-path inverse of the conformal conic differs from stock d3 by up to 80 ULPs (`pow(f/r, 1/n)` multiplies relative error by 1/n), so its tolerance in `exact.test.ts` is 128, a new key. Reversible (one constant for the cut).
- **5c-2, 2026-10-19, agent.** Brush cursor: a ring (the hard edge of the region one stroke point edits, the same clamped radius as the edit record) under the pointer, for every tool, on the globe (a `THREE.LineLoop` of 96 points lifted 0.2% above the surface) and the flat map (a closed `LineString` through the current view's `geoPath`, so it has the true projected shape and is cut at the antimeridian; its own SVG element above the map). It is redrawn per animation frame on pointer move, radius change and tool change; the falloff is not drawn and there is no live GPU preview of an edit. Reversible.
- **5c-3, 2026-10-19, agent.** Label placement is a port of Azgaar's `label-spread.ts` into the new package `packages/carto` (decision W4). Text is measured by a table of Helvetica AFM advance widths (`font-metrics.ts`), not by the DOM, so a label's size and its placement are identical in every browser, in the engine worker and in Node; styles name `Helvetica, Arial, sans-serif` (Arial is metric-compatible), one family, regular and italic, because bold and serif tables are not in the repo and fonts are the Phase 10b asset audit's. Ink boxes are runs of three non-space glyphs, as upstream. The solver runs in screen pixels of the view, keyed by the seed and the sorted label ids (upstream's seeding), with Alea from core; it is a pure function. Because the candidate set is discrete the solver can leave one graze in a tight stack (tested: six initial overlaps to at most one). Alternatives: QGIS PAL (later, per W4), a new solver (rejected: the extraction rule). Reversible.
- **5c-4, 2026-10-19, agent.** Hillshade is QGIS's renderer formula (`qgshillshaderenderer.cpp`, single and four-direction) ported to doubles, with the derivatives from a least-squares plane through each mesh cell's neighbours in its tangent plane, in sphere metres (the mesh is not a grid, so Horn's 3 × 3 stencil does not apply). QGIS's `lightAngle` is kept as QGIS uses it: its code feeds `90° − lightAngle` where GDAL has the sun's altitude, so the port reproduces QGIS's numbers for QGIS's settings (default azimuth 315°, angle 45°). Sea cells take the flat-ground gray by default (the sea floor is not shaded). Reversible.
